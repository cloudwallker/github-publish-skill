# 文件与隐私规则

## 从项目成品判定，而不是从扩展名判定

| 类别 | 默认处理 |
|---|---|
| 源码、运行资源、依赖/锁文件、必要构建配置 | 保留，扫描内容 |
| README、安装/使用/API 文档、真实示例、许可证 | 保留；不要整目录忽略 docs |
| `docs/superpowers/specs/`、`docs/superpowers/plans/`、`.superpowers/` | 排除；已进入待推历史时阻止发布 |
| 本次 AI session/transcript/history、实现任务表、临时计划和本地执行记录 | 排除；对不明确文件先看内容 |
| `.codex`、`.claude`、`.cursor`、`.agents` 内个人状态/认证/历史 | 排除；可复用的产品配置按下面的特殊规则核实 |
| AGENTS.md、CLAUDE.md、tasks.md、plan.md、notes.md | 核实：开发过程或个人指导排除；确有产品用途的公开协作说明可保留 |
| `.env`、真实凭据配置、私钥、备份、数据库导出、日志 | 排除或改为无真实秘密的示例，必要的公开证书与私钥区分 |
| `.env.example` / `.sample` / `.template` | 只在内容是占位符、无秘密时保留 |
| 缓存、虚拟环境、node_modules、临时下载与审计报告 | 排除；可重复生成的安装包、可执行文件与分发归档通常另列 Release 附件，不提交到源码树；确为仓库运行所必需的产物按实际用途保留并检查 |
| 图片、视频、PDF、二进制、压缩包 | 不能靠扩展名认定安全，检查实际内容、元数据、嵌套文件 |

Skill/插件产品应保留 `SKILL.md`、`agents/openai.yaml`、必要的 `.codex-plugin` 清单、`scripts/`、`references/`、`assets/`、测试及公开配置。不要把待发布的 Skill 本身当成 AI 对话记录。对测试数据/训练样例中的角色消息，确认是合成且确属产品后再保留。

用户明确指定的产品文件优先于普通排除建议；真实秘密仍须处理。模糊文件的内容判断由执行代理完成，必要时问一个具体问题，不把整份清单交给用户逐项确认。

## 三个集合不是同一件事

- 候选文件：原项目或独立发布目录中准备上传的版本；可用路径清单限定。
- 暂存区：Git index 实际准备提交的内容；可能与磁盘文件不同。
- 待推历史：相对于刚读取的远程分支，本次会公开的新提交，以及最终提交树。文件在历史中出现后被删除，仍可泄露。

检查脚本的 staged 模式读取整个 index；commits 模式枚举每个待推提交的树并去重相同路径/内容，不只检查净差异。脚本不会决定哪些文件该暂存或自动清理它们。

Release 附件另有一份明确清单，必须独立检查，源码三层通过不代表安装包安全。标签注释、版本说明、校验文件和附件文件名也属于发布内容。打包从已检查提交构建或导出，不直接压缩原工作区；不把旧 `.git`、被忽略文件、签名私钥、审计报告或 AI 过程资料装进附件。目录调整见 [源码组织规范](source-layout.md)，版本发布见 [Release 流程](releases.md)。

`.gitignore` 只负责将来的未跟踪文件。已跟踪的过程文件应在保护本地副本的前提下取消跟踪；如果仍存在于将推送的历史，不能通过再加一个删除提交解决。发现原有远程历史泄露时，暂停相关发布并提出撤销/轮换秘密及历史处理方案，不自行强推。

## 内容检查

Gitleaks 用于已知秘密模式，不能自动证明所有个人信息已移除。人工还应检查：真实联系人与邮箱、电话、住址、私人 URL、用户目录路径、客户数据、截图中的账户/通知/地址栏、文档作者和定位等元数据。

保留用户授权公开的 GitHub 用户名、贡献者署名及已有开源版权信息。发现联系信息先确定是否属于用户授权公开或依法应保留的署名，不能为“隐私清理”删除全部贡献者。

扫描报告、含秘密的原始 diff、完整邮箱列表、凭据 CLI 输出都不得直接展示或提交。只报告必要的文件位置和问题类别。报告中的路径也可能敏感；被脱敏路径应在本地依据文件哈希定位。

归档在临时目录检查，防止路径穿越、链接逃逸、加密包和解压膨胀。无法安全检查的归档不进入发布清单；必要时取得原始可审查文件。不得把未知二进制简单改扩展名后放行。

## 忽略规则示例

按项目实际加入精确规则，保留已有配置；不要整段盲目覆盖：

```gitignore
# Local AI development artifacts
/docs/superpowers/
/.superpowers/
/.github-publish-work/
# Local credentials; only placeholder examples may be tracked
.env
.env.*
!.env.example
!.env.sample
!.env.template
__pycache__/
.pytest_cache/
```

这只是防止未来误加的辅助，不代替发布清单或历史检查。

参考：[Gitleaks](https://github.com/gitleaks/gitleaks)、[Git ignore](https://git-scm.com/docs/gitignore)。
